# Copilot Instructions for UnderYourBed Animatronic Project

## Project Overview
This is a .NET 8 animatronic control system designed to synchronize audio playback, servo movements, and OLED eye displays. The system runs on Linux/Raspberry Pi and processes audio bundles with lip-sync data to create realistic animatronic movements.

## Platform & Deployment
- **Target Platform**: Linux/Raspberry Pi (ARM64)
- **Runtime**: .NET 8.0
- **Audio System**: ALSA (Linux audio)
- **Hardware Interfaces**: GPIO, SPI, PWM
- **Audio Tools**: FFmpeg/FFplay for cross-platform audio support

## Package Management
- **ALWAYS** use `dotnet add package` for adding NuGet packages
- **ALWAYS** use `dotnet remove package` for removing packages  
- **ALWAYS** use `dotnet list package` to check installed packages
- **NEVER** manually edit .csproj PackageReference unless absolutely necessary
- Prefer stable package versions over pre-release
- Avoid Windows-specific packages (NAudio WaveOut, MediaFoundation, etc.)

## Architecture Principles

### SOLID Principles
1. **Single Responsibility**: Each class has one reason to change
   - `AudioPlayer` - only handles audio playback
   - `ServoController` - only controls servo movements
   - `OLEDDisplay` - only manages display rendering
   - `LipSyncEngine` - only processes timing data

2. **Open/Closed**: Open for extension, closed for modification
   - Use interfaces for all hardware abstractions
   - Strategy pattern for different eye types/animations
   - Plugin architecture for different audio formats

3. **Liskov Substitution**: Derived classes must be substitutable
   - All `IDisplayDevice` implementations work interchangeably
   - All `IAudioPlayer` implementations have same contract

4. **Interface Segregation**: Many specific interfaces vs few general ones
   ```csharp
   // Good - specific interfaces
   interface IAudioPlayer { }
   interface IServoController { }
   interface IDisplayRenderer { }
   
   // Avoid - monolithic interface
   interface IAnimatronicController { /* everything */ }
   ```

5. **Dependency Inversion**: Depend on abstractions, not concretions
   ```csharp
   // Good - depends on abstraction
   public class AnimatronicOrchestrator(IAudioPlayer audioPlayer, IServoController servo)
   
   // Avoid - depends on concrete class
   public class AnimatronicOrchestrator(AudioPlayer audioPlayer, ServoController servo)
   ```

## Code Standards

### Naming Conventions
- Use PascalCase for public members
- Use camelCase for private fields with underscore prefix: `_privateField`
- Use descriptive names: `ProcessLipSyncFrame` not `Process`
- Interface names start with 'I': `IAudioPlayer`

### Error Handling
```csharp
// Use specific exceptions
throw new AudioPlaybackException("Failed to initialize audio device");

// Always provide context
catch (FileNotFoundException ex)
{
    _logger.LogError(ex, "Bundle audio file not found: {FilePath}", audioPath);
    throw new BundleLoadException($"Audio file missing: {Path.GetFileName(audioPath)}", ex);
}
```

### Async/Await
- Use async/await for I/O operations
- ConfigureAwait(false) for library code
- CancellationToken for long-running operations
```csharp
public async Task PlayAudioAsync(string filePath, CancellationToken cancellationToken = default)
{
    await LoadAudioFileAsync(filePath, cancellationToken).ConfigureAwait(false);
}
```

### Resource Management
- Always implement IDisposable for hardware resources
- Use `using` statements or `using` declarations
- Dispose in reverse order of creation

### Logging
```csharp
// Use structured logging
_logger.LogInformation("Starting audio playback for {FileName} with duration {Duration}", 
    fileName, duration);

// Log levels appropriately
_logger.LogDebug("Servo position updated to {Position}", position);      // Debug info
_logger.LogInformation("Audio playback started");                        // Important events
_logger.LogWarning("Servo calibration drift detected");                  // Potential issues
_logger.LogError(ex, "Failed to initialize display device");             // Errors
```

## Bundle Data Structure
The project processes audio bundles with this structure:
```
bundles/
└── [bundle-id]/
    ├── manifest.json          # Bundle metadata
    ├── original.m4a           # Audio file (use this, not WAV)
    ├── song.lipsync.json      # Frame timing data
    └── input.wav              # Pipeline-generated (don't use for playback)
```

### LipSync Data Format
```json
{
  "frames": [
    {
      "TimeSeconds": 0.02,
      "MouthOpen01": 0.0      // 0.0 = closed, 1.0 = fully open
    }
  ]
}
```

## Hardware Considerations

### Raspberry Pi GPIO
- Use BCM pin numbering
- Always check pin availability before use
- Implement proper cleanup in Dispose methods

### Audio on Linux
- Prefer `ffplay` over NAudio for cross-platform compatibility
- Use ALSA device names: `hw:0,0` for default
- Handle audio device busy states gracefully

### SPI Displays
- Check SPI device permissions: `/dev/spidev0.0`
- Use appropriate clock speeds for OLED displays
- Buffer display updates for smooth animation

## Testing Strategy
- Unit tests for business logic
- Integration tests for hardware interfaces (with mocks)
- Hardware-in-the-loop tests for final validation
- Use dependency injection to enable testing

## Performance Guidelines
- Target 50 FPS for smooth lip-sync (20ms frame intervals)
- Use efficient data structures for frame data
- Minimize allocations in timing-critical paths
- Pre-load graphics and audio data when possible

## Dependencies to Avoid on Linux
- `NAudio.WaveOut*` (Windows-only)
- `MediaFoundation*` (Windows-only)
- `DirectSound*` (Windows-only)
- Any package requiring Windows Media Format SDK

## Example Interface Contracts
```csharp
public interface IAudioPlayer : IDisposable
{
    Task LoadAsync(string filePath, CancellationToken cancellationToken = default);
    Task PlayAsync(CancellationToken cancellationToken = default);
    void Stop();
    bool IsPlaying { get; }
    event EventHandler PlaybackStarted;
    event EventHandler PlaybackStopped;
}

public interface IServoController : IDisposable
{
    void SetPosition(double position); // 0.0 to 1.0
    double CurrentPosition { get; }
    bool IsCalibrated { get; }
    Task CalibrateAsync(CancellationToken cancellationToken = default);
}

public interface IDisplayDevice : IDisposable
{
    Task InitializeAsync(CancellationToken cancellationToken = default);
    Task RenderFrameAsync(byte[] frameData, CancellationToken cancellationToken = default);
    Size DisplaySize { get; }
    bool IsInitialized { get; }
}
```

Remember: This is an embedded Linux project - prioritize reliability, proper resource cleanup, and hardware compatibility over feature richness.
